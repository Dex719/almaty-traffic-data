# almaty-traffic-data

Сборщик дорожных данных Алматы для исследований krisha-fair-price / baǵam.
Работает вахтами 24/7: 2ГИС — каждую минуту, Яндекс — каждые 4 минуты
(чаще сервисы сами не пересчитывают), события — каждые 5 минут:

| Что | Источник | Куда пишется |
| --- | --- | --- |
| Балл пробок, тренд, км затруднений | Яндекс `export.yandex.ru/bar/reginfo.xml?region=162` | `data/scores.csv` |
| Балл пробок | 2ГИС `jam.api.2gis.com/meta?reg=67` | `data/scores.csv` |
| ДТП, ремонты, перекрытия, комментарии водителей | 2ГИС `tugc.2gis.com/1.0/layers/user` | `data/events.json` + счётчики в `scores.csv` |
| Официальные ограничения (с сроками) | 2ГИС `tugc.2gis.com/1.0/layers/2gis` | `data/events.json` |
| Пробки посегментно, вся карта (каждые 5 мин) | тайлы Яндекса `core-jams-rdr-cache.maps.yandex.net`, z14 | `data/jam_map/YYYY-MM-DD.csv` |

Все каналы публичные, без токенов. Камеры не логируются — это статичный
справочник, а не события.

## Данные

- **`data/scores/YYYY-MM.csv`** — по строке на минутный тик: `ts_utc,
  ts_almaty, yandex_score, yandex_trend, yandex_jam_km, dgis_score,
  ev_crash, ev_roadwork, ev_restriction, ev_comment, ev_other`. Пустое
  поле = «в этот тик источник не опрашивался» (у каждого своя каденция),
  а не ноль. Файлы месячные, чтобы не раздувать git.
- **`data/events/YYYY-MM.json`** — реестр событий месяца: `id → карточка`
  с координатами, типом, текстом и парой `first_seen`/`last_seen`.
  Исчезнувшее с карты событие остаётся в реестре — по паре видно время
  жизни (сколько рассасывалось ДТП). Событие, пережившее границу месяца,
  переезжает в новый файл с сохранением `first_seen`.
- **`data/scores.csv`, `data/events.json`** — легаси первых замеров
  режима «раз в 30 минут», оставлены как есть.
- **`data/jam_map/`** — посегментные пробки всей карты. `ways.json` — реестр
  из 6 069 улиц (id OSM, класс дороги, полилиния), пишется один раз.
  `YYYY-MM-DD.csv` — по строке на срез: `ts_utc, ts_almaty, covered, classes`,
  где `classes` — строка из 6 069 символов в порядке реестра
  (`G` свободно · `Y` плотно · `R` пробка · `D` стоит · `-` нет цвета).
  Срез ~6 КБ, git хранит дельтами. Съёмка идёт фоновым потоком внутри
  вахты и не задерживает минутные тики.
- **`data/snapshots/YYYY-MM/DD.jsonl`** — на каждый замер список id активных
  событий: восстанавливает картину «что висело на карте в такой-то момент».

## Запуск

```bash
pip install -r requirements.txt
python -m collector                    # один замер → data/ (легаси-режим)
python -m collector.shift --minutes 5  # мини-вахта локально
python -m pytest tests/ -q             # оффлайн-тесты
```

## Расписание: вахта + реаниматор

**`.github/workflows/collect.yml`**. Один джоб-«вахта» живёт ~5ч40м
(лимит GitHub — 6ч): внутри цикл замеров с джиттером ±15 сек, коммит
пачкой раз в 15 минут, упавший источник получает кулдаун 10 минут и не
валит остальные. В конце вахта диспатчит следующую (workflow_dispatch
через GITHUB_TOKEN — документированное исключение из запрета рекурсии).
Если цепь порвалась, cron-реаниматор `13,43 * * * *` поднимает новую
вахту (кривые минуты — тики на :00/:30 GitHub молча выкидывает). Guard
в начале джоба не даёт двум вахтам жить одновременно.

Actions-минуты у публичных репо бесплатны без лимита. Регулярные коммиты
заодно не дают GitHub отключить schedule за 60 дней неактивности.

## Зачем

Ряд `scores.csv` + реестр событий = обучающие данные для транспортной
модели baǵam (равновесие Уордропа, калибровка по баллу) и будущей фичи
транспортной доступности в krisha-fair-price: профиль недели, эффект
ремонтов/ДТП, 1 сентября, снегопады.
