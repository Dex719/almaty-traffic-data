# Git-воркфлоу

## Ветки и слияние

- `main` — единственная долгоживущая ветка. В неё пишет бот вахты (`traffic-bot`) коммитами `data: traffic observations <UTC>` каждые 15 минут и человек — через PR.
- Ветки изменений: `feat/<slug>`, `fix/<slug>`, `docs/<slug>`; slug совпадает со слагом спеки в `.kiro/specs/`.
- PR по шаблону `.github/pull_request_template.md`: «Changes», «Verification» (офлайн-тесты, нет секретов и данных, миграция и откат описаны), «Operational limitations». CI (`Tests`, 3.12/3.13) должен быть зелёным. Слияние — обычный merge commit (история данных не переписывается).
- Dependabot: еженедельно `pip` и `github-actions`; сливать после зелёного CI, при конфликте с `collect.yml` — rebase.

## Коммиты

- Первая строка — императив по-английски, что сделано; тело — зачем и что важно операционно. Ссылки на спеку по слагу.
- **Запрещена любая AI-атрибуция**: никаких `Co-Authored-By: Claude ...`, «Generated with Claude Code» и т. п. ни в коммитах, ни в PR. Автор — только владелец.
- Данные (`data/**`) руками не редактируются и в PR не включаются; исправления данных — только кодом сборщика или отдельной спекой миграции.

## Что коммитит бот

- Только live-представления: `data/scores`, `data/events` (раз в час), `data/jam_map/ways.json`, `data/jam_map/registries`. Архивные потоки идут в Releases и перечислены в `.gitignore`.
- Теги `staging` и `data-YYYY-MM` создаёт сборщик под релизы — не удалять и не двигать; релиз `staging` внутренний.

## Внедрение изменений в публикацию (cutover)

- После merge текущая вахта дорабатывает **на старом коде** до конца (до 5,5 ч) и подтягивает `main` через `pull --rebase` каждые 15 минут. Любое изменение, влияющее на то, что старый код коммитит (например, `.gitignore`, переименование путей), должно быть безопасно для одной перекрывающей вахты.
- Если безопасность не гарантирована: отменить run (`gh run cancel`), дождаться артефакта `traffic-recovery-<run_id>`, запустить новую вахту (`gh workflow run collect.yml --ref main`), затем экспортировать хвост журнала из артефакта и отгрузить сегодняшние файлы сегментом (`python -m collector.publish ship --data-dir <artifact> --run-id recovery_<run_id>`). Отменённый run **не** ставит преемника в очередь — запуск вручную обязателен.
- Не запускать две вахты на одну ленту; `concurrency: traffic-collector` держит одну.

## Локальные особенности

- На Windows `git push` по HTTPS через HTTP/2 может рваться (408/reset); помогает `-c http.version=HTTP/1.1` или `git config --global http.version HTTP/1.1`. Credential helper: `gh auth git-credential`.
- Нетрекаемые локальные файлы вроде `build_map.py`, `traffic-map.html` — исследовательские, в коммиты не включаются.
