# Стандарты проекта

## Код

- Python с `from __future__ import annotations`, аннотации типов в сигнатурах, небольшие функции; докстринги модулей описывают контракт, а не пересказывают код.
- Новые зависимости — только с закреплением версии в `requirements*.txt` и обоснованием в спеке; предпочитать stdlib. Обновления версий приходят PR от Dependabot.
- Linux-only импорты (`fcntl`) держать в `ops.py`; модули `store`, `journal`, `publish`, `sources` должны импортироваться на любой ОС (операторский CLI запускают и с Windows).
- Логи: `logging`, уровень INFO для собственных сообщений; шумные библиотеки (`httpx`, `httpcore`) — WARNING. Никогда не логировать полные ответы источников, комментарии водителей, URL с секретами, токены (`publish.scrub`).

## Долговечность данных

- Любая запись целого файла — через временный файл в том же каталоге, `fsync`, `os.replace`, затем fsync каталога (`store.atomic_json`, `journal.atomic_bytes`).
- Append-only файлы дописываются с `flush` + `fsync`; никогда не переписываются и не «чинятся» массово.
- Журнал: одна транзакция на наблюдение, `synchronous=FULL`; состав экспортного батча фиксируется в БД до записи файла; повтор после сбоя — тот же батч.
- Идемпотентность публикации: активы Releases неизменяемы, состояние отгрузки продвигается только после подтверждённого digest; повторная отгрузка одних байт безопасна благодаря построчной дедупликации при консолидации.
- Схемы файлов и имена столбцов не меняются задним числом; новая семантика — новый файл/каталог (`jam_map/v2`, `data/events/YYYY-MM.json`), старые файлы замораживаются.

## Обработка ошибок

- Источники независимы: ошибка одного не блокирует запись результатов других; частичный результат помечается явно (`partial`, `complete=false`), а не маскируется.
- Сбои сети/квот — через `SourceGuard` (Retry-After, cooldown), не через тихие повторы в цикле.
- Публикация: неудача не удаляет локальные данные; 45 минут без успешного push/ship → ненулевой код и recovery artifact.
- Фоновая консолидация ловит все исключения внутри потока и повторяет попытку в следующем цикле.

## Тестирование

- Только офлайн: ни одного запроса к провайдерам или GitHub API. Сеть подменяется фейками (`FakeResponse`, `SimpleNamespace`-клиенты, `FakeReleases`); git проверяется на настоящем локальном bare-remote.
- Каждое требование спеки трассируется на тест (AC-x.y → имя теста в `tasks.md`/Evidence).
- Запуск: `python -m pytest tests/ -q` на Linux или в WSL; `python -m compileall -q collector`. CI: матрица 3.12/3.13 на PR и на push в `main` при изменении кода.
- Тесты не должны зависеть от раскладки репозитория (создавать нужные каталоги в `tmp`), от локали и от сети.

## Документация

- `README.md` — операторский контракт: режимы, где лежат данные, семантика, деплой, backup, безопасность. Меняется вместе с любым изменением раскладки данных или публикации.
- Спеки — `.kiro/specs/<slug>/` по канону Kiro (Feature: requirements + design + tasks; Bugfix: bugfix + tasks; Micro: пара абзацев). После реализации — статусы, Evidence, чекбоксы.
- Комментарии в коде объясняют «почему» (ограничение провайдера, семантика GitHub Actions), а не «что».

## Безопасность и приватность

- Токен GitHub — только `GH_TOKEN` из окружения Actions; в коде, remote URL, логах, PR его нет. Права workflow: `contents: write`, `actions: write` — не расширять.
- Heartbeat URL считается секретом: только HTTPS, без userinfo, не логируется.
- Recovery artifacts и дневные архивы содержат комментарии водителей: ограничивать доступ, помнить о сроках хранения; не расширять аудиторию без политики удаления.

## Бюджеты

- Тайлы карты: 4 потока, интервал 0.2 с, бюджет 120 с, один повторный проход.
- Git-публикация: 120 с на цикл; `gh` — 120 с на вызов; сегмент ≤ 64 МиБ за цикл.
- Консолидация — вне потока опроса (daemon), никогда не задерживает watchdog.
